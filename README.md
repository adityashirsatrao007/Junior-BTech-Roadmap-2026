## 1. What this repo is

A complete, day-by-day training plan across 14 topics. The two non-negotiables of the plan:

1. **Daily consistency over intensity** — small daily doses, never skipped.
2. **Build + apply > just watch** — every module ends with a *thing you make or solve*.

Each topic file has:
- what it is (from absolute 0),
- exact order to learn it,
- YouTube/course/GitHub resources (free),
- a "DO / DON'T" list,
- and a mini-project or practice target.

## 5. What to do and what NOT to do

### DO ✅
- **Solve before you watch** the solution video. 40 minutes stuck → then watch.
- Write ALL code yourself. Typing ≠ learning; your fingers must learn.
- Commit **every single day** to GitHub (foolproof Streak + proof of work).
- Keep a **notebook** (GitHub repo or Notion) — log 1 thing learned per day.
- Re-solve problems you got wrong after 7 days. **Revision > quantity.**
- Use **YouTube for concepts** (NeetCode, Striver, Love Babbar), but code it yourself.
- Practice SQL, aptitude, and DSA together — don't wait to "finish" one first.
- Ship small projects fast. A working small app beats an abandoned big one.

### DON'T ❌
- **Don't skip days.** 30 min/day beats 6 hrs on Sunday.
- **Don't collect free courses like trophies.** Finish one course 100% before starting another.
- **Don't memorise LeetCode solutions** — memorise *patterns* (two pointers, sliding window...).
- **Don't copy-paste project code** without being able to explain every line in an interview.
- **Don't put "learning XYZ" on your resume.** Only what you've *built* goes on the resume.
- **Don't buy paid courses now.** All resources here are free or have free tiers.
- **Don't compare with batchmates daily.** Compare with *yesterday-you*.

## 7. Weekly review (own it every Sunday evening — 30 min)

1. LeetCode/GFG solved count this week — on track for 1/day?
2. SQL done Tue+Sat?
3. GitHub contributions — 6+ days green?
4. Focus module progress — is the course 100% done, not 50% of 3 courses?
5. Write 3 lines in your learning journal: *things learned, stuck on, next week's plan.*

If you miss days, **repair the backlog on Sunday**, never by stacking 3 topics next Monday.

## 8. If you use AI tools (recommended, correctly)

- opencode / ChatGPT / Gemini: use them as **teaching assistants and reviewers**, not ghost-writers.
- Rule: type the code -> run it -> if stuck, ask the AI "explain my bug", not "write the solution".
- AI is a *multiplier* only when your fundamentals are real. Hollywood interviews will test you face-to-face.
